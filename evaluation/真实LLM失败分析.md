## 案例一：协议配置字段放错层级

- 需求：实验 4-10，三路由器 RIPv2，VLSM 编址，关闭自动汇总。
- 首次记录：`20261014T075558Z-generate-aaae04ff`。
- 原始错误：模型把 `routing` 放在顶层；本 DSL 要求每台设备在自身对象内定义路由协议。还将 ping 阈值降为 60%，并在描述中给出不适配当前设备的模块信息。
- 影响：Schema 阻断生成结果；降低验收阈值可能把不完整连通误写成通过。
- 工程对策：提示词明确层级，加入完整 LAN 格式示例；Schema 将可选 ping 阈值限制为 100；保留首次输出与错误，不静默搬移字段。
- 修正记录：`20261014T080028Z-generate-f1114202`。结构/语义校验、独立基准比对均通过。
- 局限：这是带反馈的同一需求重试，不能充作首次成功或独立测试。

## 案例二：OSPF 路径中的下一跳写错

- 需求：实验 4-11，从 PC0 经 Router0→Router2→Router1 到 PC1 的低代价路径。
- 首次记录：`20261014T075658Z-generate-37228e8f`，因顶层字段错误未通过。
- 第一次重试：`20261014T080146Z-generate-a7948a25`，结构/语义校验通过，但路径写为 `192.168.16.126 → 10.0.0.2 → 20.0.0.2`。
- 错误原因：`20.0.0.2` 是 Router2 接口，正确下一台 Router1 的接口为 `20.0.0.1`。字段合法不等于需求正确。
- 影响：仅按模型自拟检查验收会误拒绝正确路径，或者让模型通过改写检查标准隐藏配置错误。
- 工程对策：模型输出与独立编写的课件基准比对；实际验收可通过 `verify --oracle` 使用基准断言。重试加入独立比对错误和必要检查条件。
- 第二次重试：`20261014T080558Z-generate-db16e740`，校验和独立比对均通过。
- 局限：这是生成阶段两次修正，不是 PT 注入故障的两轮自动排障。

## 案例三：输出 Markdown 围栏

- 首次记录：`20261014T075742Z-generate-3e3e5288`。
- 错误：响应包含 Markdown YAML 围栏，最初的严格 YAML 入口无法直接解析。
- 对策：仅允许单个完整围栏的显式格式适配，记录 `single_markdown_fence_removed`；不允许任意正文、多个代码块混入。原始响应保留。
- 重试记录：`20261014T080225Z-generate-6c00f4c6`，校验与独立比对通过。旧记录仍算首次失败，未用后来新增的适配器重算成成功。

## 案例四：数字型号被 YAML 解析成整数

- 需求：课内实验 7-1 的静态路由与扩展 ACL。
- 首次记录：`20261014T081334Z-generate-f93787cb`。
- 原始片段：两台路由器均使用 `model: 2911`，解析结果是整数。Schema 允许的型号是字符串 `'2911'`。
- 拦截：`validation.json` 在 `devices/0/model`、`devices/1/model` 报错；未生成部署包，未进入意图比对。
- 对策：Schema 枚举增加显式类型，提示词要求数字型号加引号，增加回归测试，确保程序不静默把整数转换成字符串。
- 当前结果：提示词和本地校验改进已完成；真实模型重试尚未执行，不能宣称该对策已提高模型成功率。

## 补充案例：RIPv2 额外路径断言与校验器漏检

记录 `20261014T080028Z-generate-f1114202` 的额外 trace 为 192.168.16.126 → 30.0.0.2 → 192.168.16.190；后两者均属于 Router1，同一转发设备的进出接口不是两次路由跳点。原人工基准只要求双向 ping 和远端 RIP 路由，因此 compare_intent 对必需条件报通过，但未覆盖额外错误。
